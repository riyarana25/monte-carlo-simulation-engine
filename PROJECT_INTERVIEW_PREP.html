FundamentalWhat does this project do?

Answer (2 min):

"I built a full-stack web application for Monte Carlo simulations. Users can select from four different simulation domains (Buffon's Needle for π estimation, Portfolio VaR for financial risk, Barrier Options for derivatives, and Rare Events probability), adjust parameters like sample size and replication count, and get instant results with statistical metrics like confidence intervals, bias, and MSE. A key achievement is using parallel computation (4 threads) to achieve 5× speedup and implementing variance reduction techniques that improved accuracy by 3.45×."

IntermediateHow does parallel execution work?

Answer (3 min):

"The backend uses Java's ExecutorService to spawn a thread pool. When a user requests 100 replications with 4 threads, each replication is submitted as a task. The 4 threads process these tasks in parallel. Each thread gets its own Random object initialized with a deterministic seed (seed + replication_number), ensuring reproducibility while maintaining thread safety. This avoids shared mutable state. With 4 threads, we see approximately 4× speedup (minus synchronization overhead). Results are collected using Future objects and aggregated to compute final statistics."

AdvancedHow did you fix the null reference bug in results display?

Answer (2 min):

"The API returns `varianceReduction: null` for naive estimators (no variance reduction). The React component checked `if (result.varianceReduction !== undefined)` but this doesn't catch null values, causing a TypeError when calling `.toFixed()` on null. JavaScript has two falsy values: null and undefined. They're different (`null !== undefined` is true), but both should be treated as 'no value'. The fix was changing to `if (result.varianceReduction != null)` using loose equality, which catches both null and undefined. This taught me to be explicit about nullable types and test edge cases."

AdvancedExplain the variance reduction technique you implemented.

Answer (4 min):

"I implemented control variates for Portfolio VaR estimation. The idea: use a correlated random variable with known mean to reduce noise. For each simulation, I: 1. Generate correlated stock returns once 2. Compute outcome: estimated VaR using these returns 3. Compute control: vanilla call option price (also from same returns) 4. Adjust: EstimatedVaR + coefficient × (AnalyticalCallPrice - SimulatedCallPrice) The key: by using the same random returns for both, they're highly correlated. The control's variance 'captures' the randomness, which gets removed from the estimate. Results: 3.45× variance reduction. This means same accuracy with 70% fewer samples, or 70% better accuracy with same samples. Tradeoff: More complex code, requires knowing analytical control mean, only helps if control is strongly correlated."

System-DesignHow would you scale this to 1M concurrent users?

Answer (5 min):

"Current architecture handles ~1000 users. To scale to 1M: 1. Containerization: Already using Docker, easy to scale horizontally 2. Kubernetes: Deploy 1000 pods across multiple regions, auto-scale based on CPU 3. Message Queue: Kafka or AWS Kinesis for async processing (user gets jobID immediately, results computed in background) 4. Caching: Redis cache (simulations deterministic: same params = same result, ~60% cache hit rate) 5. Load Balancer: AWS ALB with rate limiting (prevent single user overloading) 6. Results Storage: S3 for long-term storage, DynamoDB for recent results Cost estimate: $150K/month (using spot instances for 70% discount) The architecture would be stateless (easy horizontal scaling), with async processing decoupling frontend from backend."

Quick Reference Resources

Key Formulas

Confidence Interval: [mean - z·SE, mean + z·SE]   where z=1.96 for 95%
Standard Error: SE = σ/√n
Bias: Bias = E[Estimate] - TrueValue  (0 = unbiased)
MSE: MSE = Bias² + Variance
Variance Reduction Ratio: VR = Var(Naive) / Var(Improved)
